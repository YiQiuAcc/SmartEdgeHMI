## 1. 目的与范围

- 目的：在真实 ESP8266 硬件上验证上位机（SmartEdgeHMI）与设备的串口链路稳定性、协议正确性、指令下发与异常恢复能力，作为 v1.2 发布的硬件侧证据。
- 范围（**以固件实际能力为准**）：
  - 串口链路仅支持 **Modbus RTU**（从站地址 1，115200 8N1）：FC03 读保持寄存器（地址 0–4）、FC06 写单寄存器（地址 1 复位 / 2 阈值 / 4 LED）。
  - **JSON-Lines 串口模式不在真实硬件验收范围内**：ESP8266 固件不通过串口发 JSON-Lines，该模式仅由 Node.js 模拟器（`Simulator/virtual-device.js`）提供；固件的 JSON 输出走 WiFi 网页接口（`:80/api/data`，1 Hz）。
  - WiFi 网页看板为固件附加功能，验收串口链路**不依赖** WiFi（`Firmware/src/secrets.h` 仅影响网页看板）。

## 3. 接线与串口参数

> 依据固件源码：UART0（`Serial`），从站地址 `SLAVE_ID=1`，T3.5 断帧超时 5 ms，接收缓冲 64 字节，板载 LED 为低电平点亮（`LED_ON=LOW`）。

| 项 | 说明 |
| --- | --- |
| 引脚 | NodeMCU UART0：TX = GPIO1（D8 侧 TX 脚）、RX = GPIO3；**与板载 USB 串口芯片共用**，烧录 / 外接适配器不能同时占用 |
| 交叉连接 | 设备 TX → 适配器 RX，设备 RX → 适配器 TX（交叉） |
| 电平 | **3.3V TTL**。必须使用 3.3V 电平的 USB-TTL 适配器；5V 电平有损坏风险；**严禁接 RS232 电平（±12V）** |
| 共地 | 适配器 GND 与 NodeMCU GND 必须共地 |
| 供电 | 首选 NodeMCU USB 口（5V 输入，板载稳压 3.3V）；外接供电时接 5V→VIN 或 3.3V→3V3，禁止从适配器与 USB 同时供 5V |
| 断帧 | Modbus T3.5 固件按 5 ms 实现：连续指令帧间隔应 > 5 ms；上位机 1s 轮询间隔满足 |
| 启动残留 | ESP8266 上电会在 UART0 输出 boot 信息（非 115200 波特率的乱码帧）；固件启动时已清空接收缓冲，上位机侧若在设备上电瞬间连接，前几帧可能异常，属预期 |

## 4. 测试矩阵

> 每项执行后将"实际 / 证据 / 判定"改写为真实结果。判定取值：通过 / 通过（带备注）/ 失败 / 阻塞。
>
> 寄存器与指令速查（与固件一致）：FC03 地址 0=温度×0.1℃、1=湿度×0.1%、2=状态（1 正常 / 4 报警）、3=错误码（报警时 302）、4=LED（0/1）；FC06 地址 1 写 1=复位（LED 快闪 3 次，温湿度回 25.0/45.0）、地址 2=阈值（值÷10 ℃）、地址 4=LED 开关（>0 亮）。
