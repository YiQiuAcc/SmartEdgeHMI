# SmartEdge-HMI 注释规范

本规范是 SmartEdge-HMI 仓库的注释唯一标准，适用于 `SmartEdgeHMI`、`SmartEdgeHMI.Watchdog`、`Shared`、`SmartEdgeHMI.Tests`、`SmartEdgeHMI.Benchmarks` 全部 C# 代码，以及 `Firmware/`、`Simulator/` 中的嵌入式与脚本代码。代码评审以本文件为准；与 IDE 模板生成的注释冲突时，以本文件为准。

核心判据只有一条：**注释必须承载代码本身无法表达的信息，否则不写。**

---

## 1. 基本原则

- 注释解释**为什么**和**约束**，代码表达**做什么**。凡是从签名、类型、命名、控制流可直接读出的信息，不重复。
- 优先解释设计原因、业务含义、协议与硬件约束、边界条件、失效后果。
- 保持准确、简洁、客观。一句话能说清就不写两句，不确定的机制不写。
- 注释与实际实现必须同步。行为变更时同一次提交内更新注释；注释无法确认时删掉，而不是保留一个可能错的描述。

判断标准：把注释删掉，读者是否还能得到同样的信息？能，则这条注释不该存在。

## 2. 注释类型与选择

| 形式 | 用途 | 不该用在哪 |
| --- | --- | --- |
| `//` | 解释特殊逻辑、设计原因、边界条件、实现约束。**默认形式。** | 逐行翻译代码、标记显而易见的步骤 |
| `///` | 对外契约：公共 API 的语义、参数约束、异常、线程模型、使用方式 | 私有成员、简单属性、自解释的方法 |
| `/* */` | 确实需要块状说明的复杂算法或多段前置条件 | 普通注释、临时禁用代码 |
| `#region` | 仅用于超长类型内的**语义分区**（如 400 行以上的测试类按测试类别分组），标题用中文 | 人为划分普通方法与字段、包裹单个成员、为折叠而折叠 |

选择顺序：`//` → `///`（有对外契约时）→ `/* */`（成段说明确有必要时）。`#region` 默认不加，只在类型确实过长且分区语义清晰时使用。

## 3. XML 文档的准入

公共 API **按复杂度与契约价值**决定是否写 XML 文档，不按可见性一刀切。

必须写：

- 公共接口（`I*`）：契约的责任边界、调用方必须遵守的前置条件、线程与生命周期约定。
- 核心服务与协议实现类：整体职责、内部并发模型、与其他组件的协作顺序。
- 重要模型 / DTO / 配置类：字段语义、单位、取值范围、默认值来源、序列化兼容性。
- 有非直观副作用或易误用的公共方法：`<remarks>` 说明副作用、`<exception>` 说明抛出条件。

不写：

- 私有成员、`internal` 实现细节（除非涉及所有权或并发约定）。
- 简单属性、常量、`record` 的位置参数——名字已经说明一切。
- 只重复方法名的 `<summary>`，例如 `/// <summary>获取温度</summary>` 配 `GetTemperature()`。
- 为消除 CS1591 而批量生成的空壳文档。本项目未开启 `GenerateDocumentationFile`，不存在此类压力。

需要时使用 `<param>`、`<returns>`、`<exception>`、`<remarks>`、`<inheritdoc />`，且描述必须是契约信息，不是参数名的中文翻译。

## 4. 必须写明的六类契约

出现下列情形时，注释是**强制**的，缺失视为评审缺陷。

1. **并发与线程**：哪些成员可在后台线程调用、哪些必须回到 UI 线程、锁保护的范围、是否可重入。例：`_syncRoot` 保护的是字典本身还是字典内对象的可变字段。
2. **异步与生命周期**：取消语义（谁的 Token 取消意味着正常退出还是故障）、超时、`Task` 是否被观察、`Dispose` 与在飞任务的时序关系。
3. **缓冲区所有权**：谁租用、谁归还、归还时机、跨线程传递后由谁负责、是否允许调用方持有引用。
4. **协议与数值**：帧格式、字节序（大端 / 小端）、寄存器地址基准、单位、缩放系数、有效范围、越界时的降级行为。
5. **状态转换与恢复**：状态机的合法迁移、非法迁移的处理、失败后的补偿或重试策略、幂等性。
6. **非直观性能优化**：为什么必须这样做（例如避免 GC 压力、避免 DI 解析、避免 UI 线程阻塞），以及放弃优化会带来的可测量后果。

## 5. 格式要求

- 统一使用中文注释，保留标准英文技术术语（`Modbus RTU`、`CRC16`、`Pipe`、`Dispatcher`、`ArrayPool` 等不翻译）。
- 技术名称、单位、协议术语必须准确：`ms`、`°C`、`%RH`、`FC03`、`N81` 等按行业惯例书写，不混用全角符号。
- 行注释使用 `//`，与所注释代码**同缩进**；注释放在被说明代码的上方；仅当说明同一行末尾的短约束时才使用行尾注释。
- 标点使用中文标点。行注释（`//`）句末不加句号，多句之间用逗号或分号分隔；XML 文档按行文正常断句，允许多句分段。
- 特殊事项使用固定标记，冒号后空一格，后接可执行信息：

```csharp
// TODO: v1.3 支持 FC16 连续写多寄存器, 当前仅单寄存器写入
// FIXME: 端口被占用时 Open 抛 UnauthorizedAccessException, 当前未区分提示
// HACK: 虚拟串口驱动不回 RTS, 强制 DtrEnable=false 规避握手卡死
// NOTE: 该分支只在 Windows 串口驱动返回 0 字节时进入
```

- 不使用装饰线（`//====`、`//----`）、感叹号、全大写强调、口语化表达（"这里我们直接..."、"注意啦"）。

## 6. 禁止事项

- 禁止逐行翻译代码（`i++; // i 自增`）。
- 禁止重复方法名、变量名或显而易见的逻辑。
- 禁止无实际价值的 XML 文档，包括空 `<summary>`、只写"构造函数"的文档。
- 禁止保留注释掉的旧代码。历史由 Git 承担，删除即删除。
- 禁止写入未经验证的行为描述（"应该不会阻塞"、"理论上线程安全"）。无法确认就不写。
- 禁止注释与实现不一致，包括单位、默认值、异常类型、线程假设。
- 禁止为凑注释数量而添加注释，也禁止用注释替代本应重命名的变量或本应拆分的函数。

## 7. 正反例（均取自本仓库）

**① 删除教科书式说明**

```csharp
// 改前: 解释 .NET 常识, 与业务无关
public void Dispose()
{
    Dispose(true);
    // 通知垃圾回收器（GC）该对象已被手动清理, 无需再调用终结器（析构函数）
    GC.SuppressFinalize(this);
}

// 改后: 只保留本类型特有的收尾约束
public void Dispose()
{
    Dispose(true);
    GC.SuppressFinalize(this);
}
```

**② 保留非直观的实现原因**

```csharp
// 读路径刻意使用同步 Read 配合 500ms 的 ReadTimeout 轮询, 而不用 DataReceived 事件或异步重叠 I/O:
// 后者在 USB 转串口设备上存在已知冲突, 会让读循环卡住不返回; 同步读超时则能让循环定时回到取消检查点
```

**③ 说明缓冲区所有权**

```csharp
// 缓冲区由 ArrayPool 租用, 写入完成后在 WriteAndReturnBufferAsync 的 finally 中归还;
// 传输层不得保留该引用, 否则会与下一次 Rent 复用同一块内存
```

**④ 契约型 XML 文档**

```csharp
/// <summary>ISA-18.2 报警状态机: UNACK / ACK / RTN_UNACK / NORMAL 四态迁移与恢复去抖</summary>
/// <remarks>
/// <c>_syncRoot</c> 保护 <c>_activeAlarms</c> 字典及其中记录的可变字段。
/// 所有公开成员可从任意线程调用; <see cref="AlarmStatesChanged"/> 在锁外触发。
/// </remarks>
```

**⑤ 反例：无价值文档**

```csharp

/// <param name="settingsService">设置服务</param>
```

## 8. 自检清单

提交前逐条确认，全部为"否"才可提交：

- [ ] 是否存在删掉后信息量不变的注释？
- [ ] 是否有 `//` 注释在复述下一行代码？
- [ ] 并发、取消、缓冲区所有权、字节序、单位这五类信息是否在该写的地方写了？
- [ ] XML 文档是否只出现在需要对外契约的成员上？
- [ ] 是否残留注释掉的代码、装饰线、感叹号、`TODO` 无负责人或无触发条件？
- [ ] 注释中出现的默认值、单位、异常类型是否与当前实现一致？

可用的粗筛命令：

```bash
# 注释掉的代码残留
grep -rnE "^\s*//\s*(public|private|protected|internal|var|if|for|foreach|while|return|await)\b" --include=*.cs .
# 装饰线
grep -rnE "^\s*//\s*[=\-*]{4,}" --include=*.cs .
# 空壳 XML 文档
grep -rn "<summary>\s*</summary>" --include=*.cs .
```

## 9. 与工具链的关系

- `.editorconfig` 只约束缩进、命名与语言特性，不约束注释内容；注释质量依靠评审与本文件。
- 不开启 `GenerateDocumentationFile`，避免用编译器警告倒逼无价值文档。
- 日志（`Log.Information` 等）与注释分工明确：注释写给维护者，日志写给运维；不把注释当作日志的替代，也不在注释里写运行期才可知的值。
